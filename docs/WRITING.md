# 글쓰기 가이드

새 글을 쓰는 방법은 두 가지입니다. 어느 쪽이든 결과는 `_posts/` 폴더의
Markdown 파일 하나이고, `main` 브랜치에 저장되면 GitHub Pages가 1~2분 뒤
사이트에 반영합니다.

| 방법 | 어디서 | 이런 분께 |
| --- | --- | --- |
| **Pages CMS** | 브라우저 (휴대폰 포함) | 편집 화면에서 쓰고 싶을 때 (권장) |
| **`npm run new`** | 내 컴퓨터 터미널 | git과 에디터로 쓰는 게 편할 때 |

## 1. Pages CMS로 쓰기

### 처음 한 번만: 연결하기

1. <https://app.pagescms.org> 에 접속해 **Sign in with GitHub** 로 로그인합니다.
2. 저장소 목록에 `nic35t.github.io`가 없으면 **Install the GitHub App** 을 눌러
   이 저장소 접근을 허용합니다.
3. `nic35t.github.io` → 브랜치 `main` 을 고르면 왼쪽에 **글**, **글 템플릿**,
   **Media** 메뉴가 보입니다.

### 새 글 발행하기

1. **글** → **Add an entry** (새 항목 추가).
2. 필드를 채웁니다.

   | 필드 | 설명 |
   | --- | --- |
   | 제목 | 한글 그대로 씁니다. |
   | 영문 주소 | **새 글이면 꼭 입력.** 글 주소와 파일 이름이 됩니다. 영문 소문자·숫자·하이픈만. 예: `stablecoin-regulation-2026` |
   | 요약 | 홈과 카드에 보이는 한두 문장. 비우면 본문 첫 문단이 쓰입니다. |
   | 발행 일시 | 기본값은 지금. 미래 시각으로 두면 발행되지 않습니다. 사이트는 저장(커밋)할 때만 다시 만들어지므로 예약 발행은 되지 않습니다. |
   | 카테고리 | 첫 번째 값이 글 주소(`/ai/…`)와 제목 위 라벨이 됩니다. |
   | 태그 | 여러 개 가능. 시리즈 글은 `원화 스테이블코인 심층분석` 을 넣으세요. |
   | 목차 표시 / 목차 고정 | 소제목(##)으로 목차를 만듭니다. 짧은 글은 꺼도 됩니다. |
   | 공개 | 끄면 **초안**: 저장은 되지만 사이트에는 안 보입니다. |
   | 대표 이미지 | 선택. 비워도 됩니다. |
   | 본문 | 기본 뼈대(일반 칼럼)가 들어 있습니다. 다른 형식은 아래 "템플릿" 참고. |

3. 저장하기 전에 위쪽의 **파일 이름**이 `2026-09-25-영문주소.md` 형태인지
   확인합니다. 날짜 뒤가 비어 있으면(`2026-09-25-.md`) 영문 주소를 빠뜨린
   것이고, 그 파일은 발행되지 않습니다.
4. **Save** → 커밋이 만들어지고, 1~2분 뒤 사이트에 나타납니다.

### 템플릿 쓰기

**글 템플릿** 메뉴에 네 가지 뼈대가 있습니다. 열어서 본문을 복사한 뒤, 새 글의
본문에 붙여 넣으세요.

| 템플릿 | 언제 |
| --- | --- |
| 일반 칼럼 | 생각·분석 글. 새 글 기본 본문과 같습니다. |
| 시리즈 글 | 원화 스테이블코인 심층분석처럼 이어지는 글. 제목은 `헤드라인: 부제` 형식. |
| 기술 · 튜토리얼 | 코드와 실행 결과를 따라 하는 글. |
| 짧은 메모 · 일기 | TIL이나 짧은 기록. 목차는 끄는 걸 권합니다. |

템플릿 내용을 고치면 다음 글부터 바뀐 뼈대를 쓰게 됩니다.

### 이미지 넣기

본문 편집기의 이미지 버튼으로 올리면 `assets/images/` 에 저장되고 본문에
링크가 들어갑니다. 한글 파일 이름은 안전한 영문 이름으로 자동 변경됩니다.
휴대폰 사진은 크기가 크니, 가능하면 가로 1600px 이하로 줄여서 올리세요.

### 기존 글 고치기 · 초안 발행

**글** 목록에서 글을 열고 고친 뒤 **Save**. 초안을 발행하려면 **공개** 를 켜고
저장합니다.

## 2. 내 컴퓨터에서 쓰기 (`npm run new`)

```bash
npm run new -- stablecoin-regulation-2026                       # 일반 칼럼
npm run new -- stablecoin-part-16 --template series --title "제목: 부제"
npm run new -- pandas-groupby --template tutorial --category Tech
npm run new -- today-til --template note --category Diary
```

`_posts/오늘날짜-영문주소.md` 가 **초안**(`published: false`)으로 만들어집니다.
본문을 쓰고 `published: true` 로 바꾼 뒤 커밋·푸시하면 발행됩니다.
미리 보려면 `npm run serve` (http://127.0.0.1:4000).

## 3. 테스트 만들기 · 고치기

`/tests/` 의 자기 점검 테스트(AI 에이전트, 투자, 디지털 자산, 기획)는 모두
`_pages/tests/` 의 데이터 파일 하나씩입니다. HTML을 만질 필요 없이 CMS의
**테스트** 메뉴에서 문구·질문·점수·결과를 고치면 페이지가 그대로 바뀌고,
새 테스트를 추가하면 `/tests/` 목록에도 자동으로 나타납니다.

### 구조 한눈에 보기

| 항목 | 설명 |
| --- | --- |
| 두 축 (A, B) | 모든 질문은 두 축 중 하나에 점수를 더합니다. 축마다 이름과 양 끝(0, 100)의 설명을 적습니다. |
| 질문 · 답변 | 답변마다 점수를 줍니다. 0이 축의 낮은 쪽이고, 질문 안의 가장 높은 점수가 최대입니다 (예: 0, 1, 2). 두 축에 비슷한 수의 질문을 나눠 주세요. |
| 개념 설명 | 답변에 개념 키를 붙이면, 결과 화면에 가장 많이 고른 개념 3개가 설명과 함께 나옵니다. |
| 결과 유형 | 다섯 개가 필요합니다: A낮음·B낮음, A낮음·B높음, A높음·B낮음, A높음·B높음, 가운데(두 축 모두 35~65). |

### 새 테스트 추가하기

1. CMS **테스트** → **Add an entry**.
2. **주소**는 `/영문-주소/` 형식으로 적습니다. 파일 이름이 여기서 정해집니다.
3. 두 축, 질문(10개 안팎), 개념 설명, 결과 유형 다섯 개를 채웁니다. 기존
   테스트 하나를 열어 두고 비교하며 쓰면 편합니다.
4. **목록 순서**로 `/tests/` 에서의 위치를 정하고 저장합니다.

결과 유형이 다섯 개 중 하나라도 빠지면, 그 위치에 해당하는 사람에게는 가운데
결과가 대신 보입니다. 답변의 개념 키가 개념 설명에 없는 키이면 그 답변은
결과 화면에 개념을 띄우지 않을 뿐, 테스트는 정상 동작합니다.

## 알아두면 좋은 것

- **파일 이름 규칙:** `YYYY-MM-DD-영문주소.md`. 날짜가 틀리거나 형식이 다르면
  글이 조용히 발행되지 않습니다. CMS와 `npm run new` 는 이 규칙대로 만듭니다.
- **홈 화면:** 가장 최근 글이 맨 위 큰 영역(히어로)에 나옵니다.
- **주소는 발행 후 바꾸지 않기:** 영문 주소나 첫 번째 카테고리를 바꾸면 글
  주소가 바뀌어, 이미 공유된 링크가 깨집니다.
- **발행 확인:** 저장 후 2~3분이 지나도 안 보이면 GitHub 저장소의 **Actions**
  탭에서 `pages build and deployment` 가 실패했는지 확인하세요.
