The order is computed once. Each entry is "<10000 - count>|", so a plain string sort puts the biggest topic first and breaks ties by name; the old nested count loop walked (1..max) x every category twice to get the same order. Section ids are unchanged (`name | slugify | downcase`), so every existing /categories/#slug link still lands. The chips wrap and do not stick (C14): eight topics fit in two or three rows, and a sticky bar would sit on top of the very headings it jumps to.
